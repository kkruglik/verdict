Responsibility map

verdict-cli / verdict-py — entry layer

  • Parse user input (YAML / Python args)
  • Load data via loader feature flags
  • Build Rule + Schema objects
  • Call validate_columns(), format output
  • No validation logic lives here

csv_loader / parquet_loader — I/O layer

  • Parse raw bytes → typed Column values
  • Normalise temporal types to μs / days since epoch
  • Surface CsvLoadingError / ParquetLoadingError
  • Behind feature flags, no impact on core API

column_checks.rs — dispatch layer

  • validate_columns() — public, iterates rules
  • validate_cols_with_rule() — constraint → check_* dispatch
  • Type guards: str operand on temporal column → Err
  • unreachable!() arms = internal consistency only
  • Converts Result errors to ValidationResult::failed()

ComparableOps / NumericOps / StringOps — ops layer

  • Pure computation on column data, no schema knowledge
  • Blanket impl covers T == storage type comparisons
  • Manual impls for cross-type (&NaiveDate, &str, col-vs-col)
  • Return Vec<Option<bool>> — None = null row, not error
  • NumericOps stays as two impls (f64 Ord problem)

TypedColumn<T, M> / Column — data layer

  • Marker types solve i64 collision (Int / DateTime / Time)
  • TypedColumn::new() is the only constructor
  • Column enum is the dispatch surface for ops traits
  • len, is_null, null_count, not_null_count live here
